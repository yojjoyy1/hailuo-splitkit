1. 安裝與啟動

需要 Node.js 18.17 以上版本：https://nodejs.org

最簡單的方式是雙擊啟動檔（會自動 npm install、開伺服器、打開瀏覽器）：

  • Windows：雙擊 啟動.bat 或 start.bat
  • macOS：雙擊 啟動.command 或 start.command。若提示無法打開，在終端執行 chmod +x 啟動.command start.command 後再雙擊。

關閉該視窗即停止服務。也可以用終端：

cd hailuo-splitkit
npm install
npm start            # 開發環境（預設 http://127.0.0.1:3000）
npm run launch       # 同上，並自動打開瀏覽器
npm run dev          # 修改程式自動重啟
npm run start:prod   # 正式環境，會讀取 config/production.json（等同 node server.js --env=production）

以上指令在 Windows / macOS / Linux 都相同。若要用環境變數臨時覆寫埠號：

# macOS / Linux
PORT=8080 npm start

# Windows PowerShell
$env:PORT=8080; npm start

# Windows CMD
set PORT=8080&& npm start

2. 設定檔 config

載入順序（後者覆蓋前者）：

  1. config/default.json：預設值（進版控）
  2. config/{NODE_ENV}.json：依環境覆寫，例如 development.json、staging.json、production.json
  3. config/local.json：本機個人設定（已列入 .gitignore）
  4. 環境變數 PORT、HOST、AI_TIMEOUT_MS

AI API Key 另存在專案根目錄的 config.js（範本 config.example.js），不寫進瀏覽器 localStorage。可直接編輯該檔，或在網頁「API Key 管理」儲存。

參數說明
server.host / server.port伺服器位址與埠號。預設只聽 127.0.0.1，避免他人透過你的伺服器使用 API Key。
server.bodyLimit單次請求大小上限（專案原始碼 + 截圖）。
ai.timeoutMs單次 AI 呼叫逾時（毫秒）。
ai.defaultMaxOutputTokens單次 AI 最大輸出 tokens；每組 Key 也可在「進階設定」個別覆寫。
ai.providers.*各供應商的官方網址、預設模型與模型建議清單。
generation.filesPerBatch每次請 AI 產生幾個檔案。調小可降低輸出被截斷的機率。
generation.maxPlanFiles產出專案的檔案數上限。
generation.maxRetriesPerFile單一檔案被截斷或漏掉時的重試次數。
generation.maxSourceCharsPerBatch每批產生時附帶的原始碼字元上限。
upload.maxContextChars規劃階段送給 AI 的原始碼總字元上限，超過的檔案只列入檔案樹。
upload.maxFileBytes單一檔案大小上限，超過會略過。
upload.ignoreDirs / ignoreFiles / textExtensions讀取專案時的過濾規則。
languages可選語言與對應框架、預設框架。可自行增加。
securityItems資安防護勾選項目。

範例：在 config/local.json 改用 8080 埠、每批只產 2 個檔案：

{
  "server": { "port": 8080 },
  "generation": { "filesPerBatch": 2 }
}

3. 使用流程

  1. 選擇主專案（必填）：點「瀏覽選擇資料夾」或直接拖曳資料夾。.env 等機敏檔與依賴資料夾會自動排除。
  2. API Key（列表為空時必填）：新增 OpenAI 或 Anthropic Key，可修改、刪除、測試，並選擇「使用中」的 Key。
  3. 分離範圍（必填）：選「只分離後端」或「前後端一起分離」。兩個產出按鈕都會依此調整。
  4. 想切割的部分（選填）：上傳/貼上截圖或文字描述；不填則由 AI 自行判斷。
  5. 簽章 signKey（選填）：可交給 AI 預設，或自訂演算法、Header、有效時間與組成規則。
  6. 語言與框架（選填）：預設 Node.js + Express.js；選「其他」語言可手填，未指定框架時使用原生無框架。
  7. 資安防護（選填）、專案架構說明（選填）、備註（選填）。
  8. 按 「切割 API 專案」 或 「建立 SKILL 架構」（選前後端一起時按鈕名稱會跟著變）。AI 會先規劃，再分批產生檔案，完成後下載 ZIP。

表單選項會自動記在瀏覽器裡，下次開啟不必重填。失敗的檔案可以按「重試失敗的檔案」重新產生。

4. 產出物：API 專案

內容會依「分離範圍」與語言框架調整。

只分離後端時，ZIP 一定包含：

  • config/（或該框架慣用的設定機制）+ .env.example：所有參數集中管理
  • docs/index.html：該專案的啟用說明網頁，直接用瀏覽器打開
  • README.md、FRONTEND_MIGRATION.md：前端改接 API 的對照表
  • frontend-sdk/：給原前端使用的 API 呼叫封裝
  • .splitter/plan.json：本次 AI 拆分規劃，方便追溯

前後端一起分離時，ZIP 會改成整包：

  • README.md、docs/index.html：如何同時啟動前端與後端
  • backend/：獨立後端 API（含 .env.example 與參數化設定）
  • frontend/：已改寫、改呼叫 API 的前端（含 SDK），不再附 FRONTEND_MIGRATION.md

切換測試區/正式區（以 Node.js 為例，實際鍵名以產出專案的 docs 為準）：

# macOS / Linux
cp .env.example .env
APP_ENV=staging npm start      # 測試區，讀取 config/staging
APP_ENV=production npm start   # 正式區，讀取 config/production

# Windows PowerShell
Copy-Item .env.example .env
$env:APP_ENV="staging"; npm start

最穩定的跨平台做法是直接在 .env 裡寫 APP_ENV=staging，不必依賴各系統的指令語法。

每個 API 模組都有開關與「mock / 真實資料」切換，可在 config 中獨立控制。

5. 產出物：SKILL 架構

「建立 SKILL 架構」會產出一套 Agent Skill（SKILL.md + references/ + templates/）。Skill 的工作流程會依「只分離後端」或「前後端一起」調整：前者只指導 Agent 拆後端；後者會要求 Agent 同時產出 backend/ 與已改寫的 frontend/。

# 放到專案內（僅此專案可用）
unzip xxx-backend-split.zip -d 你的專案/.cursor/skills/

# 或放到個人目錄（所有專案可用）
unzip xxx-backend-split.zip -d ~/.cursor/skills/

# Windows PowerShell
Expand-Archive xxx-backend-split.zip -DestinationPath "$env:USERPROFILE\.cursor\skills"

Windows 也可以直接在檔案總管按右鍵「解壓縮全部」，再把資料夾放到 %USERPROFILE%\.cursor\skills\。

接著在 Agent 對話中說「依照 xxx-backend-split skill 拆出後端 API」即可。

6. 常見問題

Q：API Key 存在哪裡？安全嗎？
存在專案根目錄的 config.js，不寫進瀏覽器 localStorage。網頁新增／修改 Key 也會寫回這個檔。請勿把填好金鑰的 config.js 傳給別人或提交版控，也請勿把伺服器開放到公開網路。
Q：檔案被截斷或產生失敗？
系統會自動改為單檔重試；仍失敗可調大 Key 的「最大輸出 Tokens」、調小 generation.filesPerBatch，或換用輸出上限較高的模型。
Q：專案太大？
規劃階段只送 upload.maxContextChars 以內的檔案（優先送含 API / 資料庫邏輯的檔案），其餘列在檔案樹。可在截圖/文字中指定重點範圍，或調高上限。
Q：可以用公司內部的 OpenAI 相容服務嗎？
可以，在 Key 的「進階設定」填入自訂 Base URL（例如 https://your-proxy/v1）。
