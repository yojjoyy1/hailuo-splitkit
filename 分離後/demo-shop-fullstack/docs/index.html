快速開始（Quick Start）

1) 啟動後端（backend/）

  1. cd backend
  2. 複製環境檔：cp .env.example .env
  3. 編輯 .env（至少設定 JWT_SECRET；其餘可保留預設）
  4. 安裝與啟動： 
    npm install
npm run dev
# 預設 http://localhost:3000
# 健康檢查：curl http://localhost:3000/healthz
若看到「SignKey: enabled=true」與「Audit: enabled=true」即代表安全中介層已啟用。

2) 啟動前端（frontend/）

  1. 於專案根目錄啟動靜態伺服器： 
    npx serve frontend
# 或以任意靜態伺服器，例如 VS Code Live Server、http-server 等
  2. 開啟 login.html 或 index.html 進行測試

注意：直接以檔案開啟（file://）可能遭遇 CORS 問題；請使用靜態伺服器並將其來源加入 backend 的 CORS_WHITELIST。

API 測試範例（curl）

1) 取得公開設定（免簽章）

curl -s http://localhost:3000/api/v1/public/settings | jq .

2) 登入以取得 JWT 與 session signKey（免簽章）

curl -s -X POST http://localhost:3000/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"username":"amy","password":"amy2025"}' | jq .
# 回應示意：
# {
#   "success": true,
#   "data": {
#     "user": { "id": 2, "username": "amy", "role": "customer", "vip": true, ... },
#     "accessToken": "eyJhbGciOiJI...", 
#     "signKey": { "keyId": "a1b2c3...", "secret": "b36f...e2", "expiresAt": 1719999999999 }
#   }
# }

3) 以 JWT + 簽章呼叫受保護路由（GET /api/v1/products）

簽名字串格式：timestamp|nonce|method|path|bodySha256，演算法：HMAC-SHA256。Header 預設：X-Sign-Timestamp、X-Sign-Nonce、X-Signature、X-Sign-KeyId。

以下提供一段 Node.js 單檔腳本示範（以環境變數注入 tokens）：

// save as sign-get-products.mjs
import crypto from 'node:crypto';
import process from 'node:process';
const base = process.env.BASE || 'http://localhost:3000';
const token = process.env.JWT;     // 從登入回應擷取 accessToken
const keyId = process.env.KEY_ID;  // 從登入回應擷取 signKey.keyId
const secret = process.env.SECRET; // 從登入回應擷取 signKey.secret

const ts = Date.now().toString();
const nonce = crypto.randomBytes(16).toString('hex');
const method = 'GET';
const path = '/api/v1/products?keyword=phone';
const body = ''; // GET 無 body
const bodySha256 = crypto.createHash('sha256').update(body).digest('hex');
const canonical = `${ts}|${nonce}|${method}|${path}|${bodySha256}`;
const sig = crypto.createHmac('sha256', secret).update(canonical).digest('hex');

const res = await fetch(base + path, {
  method,
  headers: {
    'Authorization': `Bearer ${token}`,
    'X-Sign-Timestamp': ts,
    'X-Sign-Nonce': nonce,
    'X-Signature': sig,
    'X-Sign-KeyId': keyId,
  }
});
console.log(await res.json());

執行：

BASE=http://localhost:3000 JWT=<token> KEY_ID=<keyId> SECRET=<secret> node sign-get-products.mjs

前端改寫重點

移除內容

  • js/data/*.js（種子資料改由 backend/repositories/seed/*.json）
  • js/db.js（本地假 DB 拿掉，改呼叫後端 API）
  • js/auth.js、js/pricing.js、js/payment.js（商業邏輯後端化）
  • 任何含有金鑰或萬用密碼的程式碼

新增與載入順序

  1. frontend/sdk/apiClient.js（維護 baseURL、JWT、簽章）
  2. 必要時載入 frontend/sdk/storage.js（購物車與 session 狀態）
  3. frontend/sdk/authClient.js（登入、註冊、profile、logout）
  4. 視頁面載入 pages/*.js（如 pages/shop.js、pages/login.js、pages/admin.js）

預設 ApiClient baseURL 指向 http://localhost:3000；可在瀏覽器主控台以 ApiClient.setBaseURL('http://localhost:3000') 覆寫。

簽章與白名單

  • 白名單（免簽章）：GET /api/v1/public/settings、POST /api/v1/auth/login、POST /api/v1/auth/register
  • 其餘路由需同時具備 JWT 與簽章（session signKey）。
  • 簽名內容：timestamp|nonce|method|path|bodySha256，HMAC-SHA256；Header 預設： X-Sign-Timestamp、X-Sign-Nonce、X-Signature、X-Sign-KeyId
  • 有效時間窗（SIGNKEY_WINDOW_MS，預設 5 分鐘）＋ Nonce 防重放（NONCE_TTL_MS）。

常見問題（FAQ）

呼叫 API 回 401/403？

  • 是否已登入並於 Authorization 帶上 Bearer <jwt>？
  • 是否對非白名單路由計算並附上簽章與 keyId？
  • 請確認 timestamp 未超出 SIGNKEY_WINDOW_MS，且 nonce 未重覆使用；檢查本機時間是否嚴重誤差。
  • 開發測試可暫時將 SIGNKEY_ENABLED=false 驗證問題來源（正式環境請務必開啟）。

CORS 錯誤（Access-Control-Allow-Origin）？

  • 請將前端靜態站台來源加入 backend CORS_WHITELIST（以逗號分隔）。
  • 避免以 file:// 直接開啟，請使用靜態伺服器。

如何重置種子資料？

  • 限 development 環境，且 ALLOW_DEV_RESET=true。
  • 以 admin/staff 權限呼叫 POST /api/v1/admin/reset。

錯誤回應不見 stack？

  • 統一錯誤處理預設不外洩 stack；開發可設定 ERROR_EXPOSE_STACK=true。
  • 回應含 X-Trace-Id（或 body.traceId），可對照後端日誌查詢。

安全與稽核

  • 稽核日誌自動遮罩敏感欄位（password、card、Authorization、token、apiKey、signKey 等）。
  • 統一錯誤處理避免洩漏內部堆疊；可用 traceId 交叉比對後端日誌。
  • 所有機敏設定以環境變數注入，前端不再持有任何 secret。
  • RBAC 角色建議：customer（下單/查訂單）、staff（後台查詢與更新）、admin（進階管理）。
